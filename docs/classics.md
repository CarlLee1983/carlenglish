# 經典內容維護

每篇經典是一部完整短篇或中篇故事，資料各放在 `content/classics/<id>.json`，不沿用文章的雙語段落格式。加入一份合法 JSON 後，建置會自動產生首頁文學軌卡片、`/classics/<id>/` 總覽、`/classics/<id>/<n>/` 各節頁與 sitemap 項目；節號從 1 開始。

| 欄位 | 契約 |
| --- | --- |
| `id`、`title`、`titleEn` | 全站唯一的小寫連字號 ID、中文標題、英文標題 |
| `stage`、`origin` | L1–L2 必須為 `rewrite`（教學改寫），L3–L4 必須為 `original`（原文） |
| `sourceWork` | `author`、`title`、`published`（正整數出版年），以及 `gutenberg` 的 `ebook`（正整數編號）、`url`（HTTPS）、`accessedAt`（有效 YYYY-MM-DD） |
| `rewrittenAt` | 有效 YYYY-MM-DD；改寫必填，原文禁止 |
| `parts` | 2–8 節，依閱讀順序排列 |

每節包含 `title`、不爆雷的中文 `intro`、純英文段落字串陣列 `paragraphs`、0–12 筆 `annotations` 及 2–3 題 `questions`。每則注釋有 `english`、`translation` 與選填 `note`；注釋詞須在該節正文的同一句完整出現，正文第一次出現處會連到注釋，注釋也能連回。提問有 `question`、`answer`，只有最後一節另有 1–2 題 `wholeQuestions`；其他節禁止此欄位。任何層級的未知欄位會驗證失敗。

每節建議字數為 L1 150–300、L2 300–500、L3–L4 600–1,200；超出會警告，不阻擋建置。欄位錯誤、級別與版本不符、同原作同級別重複，或 ID 與場景／文章／詞表衝突則會失敗。`pnpm run build` 會先執行內容驗證。

以原作的作者、書名與出版年精確配對其他版本，因此同一原作的不同級別須沿用這三個值。Gutenberg 電子書可能是作品集；出版年填這篇作品初次出版年，版本連結則指實際取用的電子書。L3–L4 去除 Gutenberg 頁首頁尾及授權聲明後，保留完整故事的用字、拼字、標點與順序，只在段落邊界切節；不得用刪節後的文字標示原文。信件換行可保留在段落字串中。不附全文中譯、音檔或插圖。建置不會連網比對原文，內容編輯仍須核對來源。

注釋詞可手動加入複習，新卡例句取自正文第一個包含該詞的句子。英文詞與意思相同時合併為既有字卡，保留既有例句與排程，另掛經典該節的來源連結；從不同節加入可保留不同來源。內容作者應沿用既有同義詞的中文字串，避免把相同意思寫成不同字卡。

續讀只記最後打開的節號，不表示讀懂或完成率。它與字卡狀態分開儲存、不進字卡備份；瀏覽器拒絕儲存時仍可閱讀。讀後提問不保存作答。回復舊版程式時，若使用者已存過經典來源字卡，仍須保留 `classic` 來源的讀取支援，避免舊解析器拒絕整份複習紀錄。
